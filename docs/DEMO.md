## 大陆普通网络验收表

这是完整真人服务的验收目标和记录模板，**当前没有填写实测结果**。每个样本只代表记录的城市、接入方式、设备、时间和版本；不能凭一个城市的一条线路推断全国可用。使用本轮 Sites 真实服务记录结果；0.5 评审页或本地适配器不能填作跨端消息、权限或断线恢复通过。

### 测量口径

- **冷载入：连续完成三次独立冷载入，每次不超过 5 秒。** 清除站点资源缓存或使用新的独立浏览器上下文，从开始导航到首屏可用、主要控件可操作；不把暖缓存刷新冒充冷载入。采用新上下文时，把访客会话建立及大厅可用纳入计时；首次昵称输入的人为耗时单独注明；不把网络加载时间和人工停留混在一起。
- **跨客户端消息：不超过 3 秒。** 同房至少验证 A→B、B→A 各一次，并覆盖文字与贴纸；从发送端点击发送到接收端出现完整消息，记录较慢值。使用共同录像或已核对时钟，不能只以服务端处理耗时代表端到端时延。内容、实际作者、顺序必须正确。
- **断网补齐：不超过 10 秒。** 仅断开一个客户端约 20 秒，期间另一个客户端发送一条带标记文字和一张约定贴纸；从网络恢复可用到遗漏消息完整出现。丢失或重复任一条均不通过，不能只记录连接图标恢复。
- 普通网络样本必须记录是否经过代理、VPN 或其他流量转发。代理样本可以另列诊断结果，不能替代普通直连验收。运营商按实际互联网出口记录，不根据 Wi-Fi 名称猜测。

这些阈值是本项目提出的验收目标，不是第三方行业标准，也不是本次已测性能。任一轮超过目标，应记录实际值、现象和复测结果；不得仅删除慢的一轮取最好结果。

## 故障处理与备用路径

先区分域名／TLS、页面资源、访客会话、API、数据库、权限和单设备网络。保留错误状态与服务版本，使用一个最小交互复现；首页可打开不证明多人正常，一个请求失败也不证明整个平台不可用。

如果只是单设备异常，保留其 Cookie 和未发草稿，先手动同步或刷新，不清空身份。昵称不是登录凭据，清 Cookie 后填同名无法恢复原房主。临时断线不会释放角色，也不应该反复刷加入提示。

如果是服务端候选缺陷，修复具体问题并发布同 schema 的新 Worker，或者回退到已验证的兼容 Worker 版本。回退源代码前核对 D1 已应用结构和环境版本；0.5 浏览器本机评审不是满足本轮要求的功能回退。

如果实际大陆或现场网络访问 Sites 被阻断，记录可复现的 DNS／TLS／API 证据，由本地 Codex 核对用户已有、已授权的独立主机和对外入口。当前保留的 Python 服务可用于后续独立部署，但它不会自动拥有 D1 当前业务数据。需要延续记录时，必须先完成受限一致性导出、隔离恢复验证、旧站写入冻结和唯一入口切换；不能同时让两个独立库承接同一批用户。

若临场公网确实不可用，可在明确说明后使用经过验证的同版本局域网真人联机，或者播放有日期／版本的真实彩排录像。局域网或录像不计作“大陆用户可打开的真人多人测试链接”交付，仍须记录未满足项与修复路径。禁止用本地 adapter 或自动聊天伪造实时互动。

## 更新规则

功能、传输、权限、内容、部署或数据结构改变时，更新应用版本、API／维护说明、发布回执与受影响的验证。旧版截图、DOM 和协议探针保留为历史，不替代新候选证据。每次测试填实际设备、时间、网络、代理状态、URL、版本、结果和证据位置；未验证项不留空暗示通过。

准备用于 GitHub 的公开源码与包含第三方美术的当前演示包分开处理，见 OPEN_SOURCE。公开材料不带 Cookie、CSRF、维护密钥、真实后台正文、举报证据或数据导出。

## 0.7发送与部署验收补充

新候选由维护者填写实际URL/release/digest后再做三位真人、至少一台真手机、深浅主题/中文输入/减少动态效果检查。公开示例素材与本地原演示素材分别记录，不将原Sites截图冒充当前sample渲染。

发送需覆盖ACK与sync两种顺序、丢ACK、晚到错误、原ID原内容重试、刷新恢复、文字新草稿和贴纸不清文字；每次逻辑发送仅一条。POST确认不跳游标。网络样本保留全部失败、样本数和p50/p95/max；少量样本仅报告范围。

目标：本地消息显示争取100ms内；稳定网络跨端争取1s内、3s为演示阻断；冷载入5s、恢复补齐10s。它们仍是待实测目标。分开记录点击→本地显示、请求→持久化、DB操作、通知、接收补齐/渲染，与旧Sites同设备同网络对照。不能把乐观显示当跨端送达或把旧轮询间隔当实际延迟。
