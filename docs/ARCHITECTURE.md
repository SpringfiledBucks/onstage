# 0.9 账户与社区实现边界

新用户端/管理端位于 apps/web 与 apps/admin，React/TypeScript/Vite独立输出 build/web、build/admin。packages/api-client负责Cookie/CSRF/运行时地址；packages/media复用经过验证的素材哈希与原图回退。新壳通过同源 /play/index.html 复用原聊天状态机；这是渐进迁移的过渡架构，尚未把聊天完整改为React。原ACK/sync同逻辑对账、身份范围、成员/频道/client_message_id、草稿和游标均保留。

Python按accounts、room_features、community、telemetry拆分领域模块，由Store组合并共享原短事务与PG房间行锁。为避免破坏旧外键、成员ID与消息幂等，users关联稳定principal_session_id；该sessions行没有可恢复的bearer且不含登录名，实际登录在auth_sessions中独立轮换/撤销。这是明确的身份桥接，后续可另行展开user外键迁移；不是继续把登录会话当账户。

PG写锁按稳定principal而非设备令牌分组，房间状态/抢角/场景/消息仍同事务；社区按账户串行限流，管理操作留account_audit。用户名、账号ID不进入普通成员DTO/分享；评分公开聚合，赞踩和举报管理专用。数据库级唯一约束保护规范化用户名、每局评分、成员评价、分享选择与场景操作幂等。

Alembic revision 20261020_01追加账户/房间/社区表，保留base schema4。生产必须独立迁移，启动和ready核验版本，不由Pod自动DDL。SQLite首次扩展旧schema4前留一致性备份。快照v2覆盖全部新表、身份哈希、快照与权限；兼容导入完整v1旧库，禁止非空目标恢复。SQLite/D1/离线旧版合同仍在，D1/离线没有本版本新账户功能。

在线以90秒账户/设备租约判定，房间租约绑定实际auth_session；同账户多设备去重。房主与当前演员均离线后再观察10分钟；旁观者不续局、临时断线不退角。进程启动或调度长停顿重置观察，避免服务故障结束对局。每20秒最多扫描200房轮转处理，确认结束同事务写系统事件；因此不是断线第600秒必然精确触发。

排名分页存5分钟有界房间ID快照，同条件复用并在每页重检当前权限；隐藏和私密权限不被旧快照绕过。该版本面向千级累计房间，仍不支持多副本/多worker，也不宣称千个活跃房并发。单进程Hub的通知、在线和连接限制保持原边界。

Python功能/接口与恢复验收稳定后再评估语言替换；先按数据库与端到端耗时判断瓶颈。若确需替换，使用同一OpenAPI、消息ID/游标、权限与并发合同逐模块验证，不能凭语言基准推断实际收益。原生客户端继续暂缓，PWA沿用公开美术缓存。

# Onstage 0.8 架构

## 0.8资源、列表和渲染

原始美术和`docs/ASSET_MANIFEST.json`冻结保留。`static/assets-manifest.json`将185个旧URL映射到内容SHA256命名的WebP，163张PNG采用严格lossless/exact、其余22张保留现有WebP字节。构建时逐像素及ICC验证，只采用更小文件，不缩图、不减色、不用near-lossless。版权来源仍由原始清单承载。部署直接使用提交产物，不在启动时运行编码器；新增素材通过工具生成和审查。

前端原始目录、历史贴纸/举报快照不改写，只在显示时解析资源清单；清单不可用时原路径仍完整可用。清单读取与会话/目录请求并行，1.2秒后降级，避免阻塞访客入场。哈希资源HTTP immutable；其他静态入口重新校验，API/错误响应no-store，gzip只处理文本。消息DOM按身份/房间/频道和消息ID复用，只替换真正变化的消息节点；ACK/sync对账和分页游标规则保持。

PWA仅缓存同源无query的哈希WebP，下载校验SHA/MIME；API、导航HTML、脚本、身份和聊天不由SW缓存。256文件/24MiB有界淘汰，主动保存并发3、单资源15秒，可取消，清除只作用于本应用美术缓存。首访无整库预载，不强制skipWaiting或刷新。新资源换hash，未变资源沿用原URL；存储被清理或超额淘汰后可重新获取。安装不等于离线多人服务。

房间接口为`created_at DESC,id ASC`键集分页，筛选/封禁/身份范围在数据库中核验；游标不承担授权。Python与D1批量读取本页成员，避免每间房独立查询。前端仅保留当前24间与页游标，筛选/刷新回第一页，丢弃旧请求的迟到响应。翻页期间新房和状态变化并非冻结快照，刷新可取得最新列表。默认活跃房10、WS连接100等准入限制仍独立存在，千房历史分页不代表千房并发验收。

## 事务和一致性

`app/store.py` 维护共享领域规则、命名参数 SQL；`app/postgres.py` 使用 SQLAlchemy 连接池与 psycopg，PostgreSQL schema 单独维护。没有运行时 SQL 文本翻译器。PG 迁移由 `tools/database.py migrate` 显式执行，应用启动只检查 schema 4。

写事务锁顺序为会话 advisory 锁（同会话跨房限流）、相关 admission 锁（仅创建会话/房间容量）、房间行锁、举报行锁。维护者结案先定位不可变房间 ID，再按房间→举报顺序锁定。角色唯一和消息幂等还有数据库约束兜底。读使用 REPEATABLE READ 快照，授权与所读后台/举报保持同一时点。超时回滚并返回未确认，客户端保留原 ID 重试；不以错误推断原发送一定未写入。

频道 `seq` 在房间事务内分配，可随业务回滚；report/rate 的真实 identity 字段导入后校正序列。成员改变、权限检查、系统事件与消息序号在同一事务内。数据库共享不会共享内存 Hub。

## 发送与恢复

本轮保留每房一条 pending，允许继续编辑新草稿。pending 有身份范围/room/member/channel/client ID 及原内容快照。ACK 和 sync 先统一对账，再按服务端消息 ID 去重；成功不可倒退。POST 确认不推进分页游标，sync cursor 仅指实际交付消息。贴纸发送不清文字草稿。响应 `client_message_id` 仅为对账标识，不提供绕过权限的查询入口。

写入确认只等待持久化。Hub 维护一个生命周期调度任务，每连接最多一个发送任务，连接上限 100；房间提示合并，慢连接有发送与关闭期限，不为每条消息创建无界任务。WS 只发失效提示，HTTP 补齐保存的正文。接收异常/重连不释放角色。

首个部署严格单副本、单 worker，更新 Recreate，允许短暂重连。未实现/验收跨实例通知、presence、限制和撤权前不扩容，亦不采用短暂双实例蓝绿部署。

## 运维和观测

维护、迁移、备份、恢复和导入读取同一个 DATABASE_URL；旧 SQLite 路径明确标注。恢复拒绝覆盖已有业务数据，先在隔离 PG 检查字段/外键/稳定 ID/游标/贴纸/举报。ONSTAGE_WRITE_FROZEN=1 阻止业务 HTTP 写入，GET 和维护者导出保留；需部署/重启后实际探测才算冻结。

X-Request-ID 与 Server-Timing 提供 HTTP/DB 操作时长；DB 计时包含线程排队、锁/连接等待及领域操作，不等于纯 SQL 执行时间。通知耗时单独日志记录。前端与真实设备端到端测量另计；本地乐观显示不等于跨端送达。当前没有大陆/现场/Sites同设备延迟结论。

新域名 Cookie 不自动迁移，昵称只显示，不能找回或合并权限。当前交付范围为开发/验证/公开 GitHub；实际迁库、部署、GitOps 和真人网络验收由后续维护者执行。详见 RUNBOOK、SELF_HOSTED、acceptance。
